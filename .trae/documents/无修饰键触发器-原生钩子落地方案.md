# 无修饰键触发器 + 原生低层钩子 — 落地方案（v2）

> v2 相对 v1 的变化：① 新增 `hookKey` 字段承担无痕绑定，`key` 字段**一字不动**，保证「旧版本可回退 + 一键回退到原路径」；② 词表收录 `F1`–`F12`，并给出浏览器按键冲突表；③ 默认开启无痕模式；④ 新增「功能键单键模式」可选预设；⑤ 新增「降级可逆性」不变量与对应单测。

---

## 0. 目标与硬约束

### 要解决的问题

现状（[shortcuts.ts](file:///d:/projects/playground/interview-coder-cn/src/main/input/shortcuts.ts#L397-L418) 走 `globalShortcut.register`）下，快捷键 `Ctrl+H` 会因为 Windows 输入管线顺序，把 `Ctrl` 的 keydown/keyup **原样投递给前台窗口（浏览器）**，只有末键 `H` 被系统吃掉。页面因此能看到「孤儿修饰键序列」，可据此判定存在隐藏快捷键。

### 交付物

让快捷键在**浏览器页面 JS 与浏览器扩展**这两层观测面上**完全无痕**（keydown / keyup / auxclick 收不到任何事件）。

### 两条硬约束（用户明确要求）

**约束 A：已有功能不受影响，且能正常回退到原路径。**
落实为三级回退（§2.6）+ 一条机器可验证的不变量（§2.5）：
- `key` / `defaultKey` 字段**不改写**，旧版本代码读到的数据与升级前完全一致；
- 关掉「无痕模式」总开关 → 全部绑定立刻回到 `key` 字段 → 与升级前 100% 一致；
- 不变量：`toFallbackAccelerator(hookDefaultKey, platform) === defaultKey`，用单测对全部 17 条 × 2 平台固定住。

**约束 B：触发器不能假设 F13–F24。**
词表收录 `F1`–`F12`（作为可选单键触发，附浏览器冲突提示），默认方案不依赖这两类键（见 §2.2）。

### 明确不做（本轮）

- 不做按设备的按键过滤（Windows 存在硬性 API 顺序限制，见 §5）。
- 不绕过独立桌面监考代理 / 锁定浏览器客户端（进程枚举、设备枚举、摄像头不在范围）。
- 不做内核驱动级拦截、不做 `WH_KEYBOARD` DLL 注入。
- 不支持 Linux。

## 2. 核心设计

### 2.1 双通道 + 三态

| 通道 | 数据来源 | 实现 | 页面可见性 |
|---|---|---|---|
| `hook` | `hookKey` 字段 | native 低层钩子吞掉整段按键 | **完全不可见** |
| `system` | `key` 字段 | 现有 `globalShortcut` | 修饰键泄漏（现状） |

绑定激活优先级：

```
无痕模式开启 且 钩子可用  →  用 hookKey（hook 通道）
否则                      →  用 key（system 通道，即升级前行为）
```

### 2.2 hook token 词表

**A. 牺牲修饰键（PREFIX，必须 + 一个主键）**

| token | Windows | macOS | 说明 |
|---|---|---|---|
| `RightControl` | 右 Ctrl（Win 默认前缀） | 右 Control | |
| `RightAlt` | 右 Alt（AltGr 布局慎用） | 右 Option ⌥（mac 默认前缀之一） | |
| `RightCommand` | — | 右 ⌘（mac 默认前缀之二） | |
| `RightShift` | 右 Shift | 右 Shift | 备用 |

> 「牺牲」的含义：该修饰键被本应用**完全接管**，在钩子启用期间不再作为 Ctrl/⌥/⌘ 使用。设置页必须显式提示。

**B. 专属单键（STANDALONE，本身即完整绑定，不能作前缀）**

`F1`–`F24`、`ScrollLock`、`Pause`、`Mouse4`（后退侧键）、`Mouse5`（前进侧键）

**`F1`–`F12` 的浏览器冲突表**（驱动设置页的冲突徽章与「功能键单键模式」的二次确认文案）：

| token | 浏览器/系统默认行为 | 单键可用性 |
|---|---|---|
| `F1` | 打开帮助 | ⚠️ 抢占 |
| `F2` | 无 | ✅ 安全 |
| `F3` | 页内查找 | ⚠️ 抢占 |
| `F4` | 无（`Alt+F4` 才是关窗） | ✅ 安全 |
| `F5` | 刷新 | ⚠️ 抢占 |
| `F6` | 定位地址栏 | ⚠️ 抢占 |
| `F7` | Chrome 光标浏览确认 | ⚠️ 抢占 |
| `F8` | 无 | ✅ 安全 |
| `F9` | 无 | ✅ 安全 |
| `F10` | 激活浏览器菜单栏 | ◐ 可用但有行为 |
| `F11` | 全屏（考试站点常用） | ⚠️ 抢占 |

**「功能键单键模式」可选预设**（设置页按钮 + 二次确认，不改动其余动作）：

| action | 预设单键 | 冲突 |
|---|---|---|
| `appendScreenshot` | `F9` | 无 |
| `stopSolutionStream` | `F8` | 无 |
| `toggleTranscription` | `F4` | 无 |
| `pageUp` | `F10` | 会激活浏览器菜单栏 |
| `pageDown` | `F2` | 无 |

其余 12 个动作保持组合式 `hookKey`。预设执行时同步写 `hookKey` 与 `key`（同为 `F8`/`F9`…，`globalShortcut` 原生支持 F1–F24，降级 100% 等价）。用户可用已有的「重置默认快捷键」回到组合式。

### 2.3 吞键状态机（关键语义）

统一语义：**只要任一前缀键处于按下状态，其后的所有按键一律吞掉**（无论是否匹配到绑定）。

```
prefixDown = Set<vk>

keydown(vk):
  if vk ∈ prefixVks:  { prefixDown.add(vk); return SWALLOW }
  if vk ∈ standaloneVks: { emit trigger(id(vk)); return SWALLOW }
  if prefixDown ≠ ∅:
      binding = match(prefixDown, modifiers(), vk)
      if binding: emit trigger(binding.id)      // 异步派发，几 ms 无感
      return SWALLOW                            // ← 不匹配也吞，避免"意外打字"
  return PASS

keyup(vk):
  if vk ∈ prefixVks: { prefixDown.delete(vk); return SWALLOW }
  if vk ∈ standaloneVks: return SWALLOW
  if prefixDown ≠ ∅: return SWALLOW
  return PASS

mousedown/up(XBUTTON1|2):                        // Mouse4 / Mouse5 专属单键
  if button ∈ boundButtons: { emit trigger(...); return SWALLOW }
  return PASS
```

好处：前缀键与主键的 down/up **全部被吞** → 页面零事件；不存在「前缀已吞、主键放行」造成的孤儿修饰键；状态机无时序竞态。

### 2.4 数据模型：新增 `hookKey`，`key` 不动（硬约束 A 的技术落点）

```ts
export type Shortcut = {
  action: string
  key: string            // 永远是可被 globalShortcut 注册的 accelerator（升级前语义，不改写）
  defaultKey: string
  hookKey?: string       // 新增：无痕 accelerator；缺失 = 该动作不自带无痕绑定
  hookDefaultKey?: string
  category: string
  status?: ShortcutStatus
}
```

- 激活优先级见 §2.1：`hookKey && hookEnabled && hookAvailable ? hookKey : key`。
- 录到 hook token 时：`hookKey = 'RightControl+H'`，同时 `key = toFallbackAccelerator('RightControl+H', platform) = 'CommandOrControl+H'`；无法降级的 token（`Mouse4`）→ `key = ''`。
- 录到普通 accelerator 时：`key = 'Control+H'`，`hookKey = undefined`。
- 判定「用户是否自定义过」：`key !== defaultKey || hookKey !== hookDefaultKey`（[ResetDefaultShortcuts](file:///d:/projects/playground/interview-coder-cn/src/renderer/src/settings/CustomShortcuts.tsx#L175-L197) 与迁移逻辑都改用它）。

**为什么这样能满足约束 A：**

| 回退场景 | 机制 | 结果 |
|---|---|---|
| 用户关掉「无痕模式」开关 | 全部绑定改用 `key` | 与升级前**逐字节一致** |
| 用户点「重置默认快捷键」 | `key = defaultKey`、`hookKey = hookDefaultKey` | 回到组合式无痕默认 |
| App 回退到 v2.0.x 旧版本 | 旧代码只读 `key` / `defaultKey`，而这两个字段**从未被改写** | 快捷键**照常工作**，无失效风险 |
| native 模块缺失 / 权限未授予 | 自动降级到 `key` | 与升级前一致（另见 §2.5 不变量） |

> zustand persist 的合并只发生在 `shortcuts` 的 action 层级（`{...defaults, ...state.shortcuts}`，见 [migrate](file:///d:/projects/playground/interview-coder-cn/src/renderer/src/lib/store/shortcuts.ts#L144-L174)），**不会深入单个 Shortcut 对象**，所以新增字段必须在 migrate 里显式补 —— 因此需要 bump `version: 7 → 8`。

### 2.5 默认值对照表 + 降级可逆性不变量

Win 前缀 = `RightControl`；mac 需**两个**前缀：`RightAlt`（对应 v7 的 `Alt` 系列）与 `RightCommand`（对应 v7 的 `CommandOrControl` 系列）。

| increaseOpacity | `CommandOrControl+Shift+Up` | `RightControl+Shift+Up` | `Alt+Shift+Up` | `RightAlt+Shift+Up` |
| decreaseOpacity | `CommandOrControl+Shift+Down` | `RightControl+Shift+Down` | `Alt+Shift+Down` | `RightAlt+Shift+Down` |
| appendScreenshot | `CommandOrControl+Shift+Enter` | `RightControl+Shift+Enter` | `Alt+Shift+Enter` | `RightAlt+Shift+Enter` |
| stopSolutionStream | `CommandOrControl+.` | `RightControl+.` | `Alt+.` | `RightAlt+.` |

| clearTranscription | `CommandOrControl+Shift+T` | `RightControl+Shift+T` | `Alt+Shift+T` | `RightAlt+Shift+T` |
| pageUp | `CommandOrControl+J` | `RightControl+J` | `CommandOrControl+J` | `RightCommand+J` |

**降级映射（平台相关）**

| hook token | → Win | → macOS |
|---|---|---|
| `RightControl` | `CommandOrControl` | `Control` |
| `RightAlt` | `Alt` | `Alt` |
| `RightCommand` | `CommandOrControl` | `CommandOrControl` |
| `RightShift` | `Shift` | `Shift` |
| `F1`–`F24` | 同名 | 同名 |
| `ScrollLock` / `Pause` | 同名（实现时确认 Electron token 拼写，不支持则返回 `null` → `unsupported`） | 同左 |

`toFallbackAccelerator(accelerator, platform)` 签名需带平台（共享包不能用 `navigator`）。

**不变量（用单测固定）**

```
对全部 17 条默认快捷键 × {win32, darwin}：
  toFallbackAccelerator(hookDefaultKey, platform) === defaultKey
```

这条不变量就是「降级后键位与升级前完全一致」的机器化证明，也是约束 A 的核心保障。

### 2.6 三级回退

| 级别 | 触发方式 | 行为 |
|---|---|---|
| L1 运行时降级 | 钩子不可用 / 用户关开关 / 健康检查失败 | 绑定切回 `key`，走 `globalShortcut`（键位 = 升级前） |
| L2 用户手动回退 | 设置页「无痕模式」总开关（默认**开**）+ 已有「重置默认快捷键」 | 一键回到 system 通道 |
| L3 版本回退 | 安装回 v2.0.x | 旧代码只读 `key`/`defaultKey`，字段未被改写 → 正常工作 |

### 2.7 钩子安装 / 降级 / 自愈

```
启动：app.whenReady() → hookRuntime.init()
  ├─ 读 settings.hookShortcutsEnabled（默认 true）；false 则直接走 L1，不加载 addon
  ├─ loadNativeAddon()            // 失败 → reason='no-addon'
  ├─ addon.install(...)           // 返回 false → reason='failed'
  ├─ mac: AXIsProcessTrustedWithOptions → 未授权 → reason='permission-denied'
  └─ 成功 → available=true，hook 绑定生效
```

**Windows 失联自愈**：LL 钩子回调超时会被系统**静默摘除**且无通知。用系统空闲时间交叉校验：

```
每 3s:
  systemIdleMs = now - GetLastInputInfo().dwTime
  hookSilentMs = now - lastEventTick
  if hookSilentMs > 5000 && systemIdleMs < hookSilentMs - 1000:
      reinstall()      // 系统明明有输入，我们却没收到 → 钩子已被摘
```

**macOS 失联自愈**：tap 回调内收到 `kCGEventTapDisabledByTimeout` / `kCGEventTapDisabledByUserInput` 时立即 `CGEventTapEnable(tap, true)`，原生侧完成，不上报 JS。

## 3. 具体改动

### 3.1 新增共享包 `packages/shortcut-tokens`

**为什么建包**：token 词表有 6 个消费点、跨 2 个进程（渲染端录键 / 显示 / 通道判定，主进程通道判定 / 降级映射 / 绑定编译）。词表漂移的失败模式是「静默泄漏」——最不该靠人工同步的地方。repo 已有 `packages/sync-protocol` 这个「无构建步骤的共享 TS 包」先例。

**新增文件**
- `packages/shortcut-tokens/package.json` — 照抄 `packages/sync-protocol/package.json` 结构（`private: true`、`type: module`、`exports` 指向 `./src/index.ts`、无 dependencies）。
- `packages/shortcut-tokens/src/index.ts`：

```ts
export const PREFIX_TOKENS = ['RightControl', 'RightAlt', 'RightCommand', 'RightShift'] as const
export const STANDALONE_TOKENS = [
  'F1','F2', /* … */ 'F24',
  'ScrollLock','Pause','Mouse4','Mouse5'
] as const
export const HOOK_TOKENS: ReadonlySet<string> = new Set([...PREFIX_TOKENS, ...STANDALONE_TOKENS])

export type Platform = 'win32' | 'darwin'

export function splitAccelerator(accelerator: string): string[]
export function isHookToken(token: string): boolean
export function isHookAccelerator(accelerator: string): boolean
export function isPrefixAccelerator(accelerator: string): boolean
```

**为什么状态机放原生侧**：macOS 的 `CGEventTap` 回调必须在 tap 线程上**同步**决定吞/放，而 napi 不允许从非主线程同步调用 JS。把状态机（约 60 行）放原生、用 N-API 线程安全函数异步回调 `onTrigger`，两平台行为一致、无竞态。

**原生实现要点**

- Windows（`src/win/hook_win.cc`）
  - `install` 在调用线程（= Electron 主进程主线程，有消息循环）执行 `SetWindowsHookEx(WH_KEYBOARD_LL, ...)`；`mouseButtons` 非空时才挂 `WH_MOUSE_LL`。
  - 回调返回 `1` 吞事件，否则 `CallNextHookEx(...)`。
  - 键码：`KBDLLHOOKSTRUCT.vkCode` 为主，辅以 `flags & LLKHF_EXTENDED` 校验左右（右 Ctrl/右 Alt/右 Shift 期望 `0xA3 / 0xA5 / 0xA1`，**实现时实测确认**）。
  - `flags & LLKHF_INJECTED` 的事件直接放行（防自触发）。
  - 鼠标：只处理 `WM_XBUTTONDOWN/UP`，`MSLLHOOKSTRUCT.mouseData >> 16` 为 `XBUTTON1/2`；其余消息立即 `CallNextHookEx`，避免鼠标事件开销。
  - `listInputDevices` / `identifyDevice`：`GetRawInputDeviceList` + `GetRawInputDeviceInfoW(RIDI_DEVICENAME)` 枚举；`identifyDevice` 用 message-only 窗口（`HWND_MESSAGE`）注册 `RIDEV_INPUTSINK` 抓下一个 `WM_INPUT` 的 `header.hDevice`，超时返回 `null`。
- macOS（`src/mac/hook_mac.mm`）
  - `AXIsProcessTrustedWithOptions({ kAXTrustedCheckOptionPrompt: true })` 触发授权。
  - `CGEventTapCreate(kCGSessionEventTap, kCGHeadInsertEventTap, kCGEventTapOptionDefault, mask, ...)`，mask 覆盖 `kCGEventKeyDown/KeyUp/FlagsChanged/OtherMouseDown/OtherMouseUp`；回调返回 `NULL` 删除事件。
  - 修饰键走 `kCGEventFlagsChanged`，用 `CGEventGetIntegerValueField(event, kCGKeyboardEventKeycode)` 区分左右（Control=0x3B、RightControl=0x3E、Option=0x3A、RightOption=0x3D、RightShift=0x3C、RightCommand=0x36，**实现时实测确认**）。
  - 侧键：`kCGEventOtherMouseDown/Up` + `kCGMouseEventButtonNumber`。
  - tap 失效内联自愈（§2.7）。
  - 打包需在 [electron-builder.yml](file:///d:/projects/playground/interview-coder-cn/electron-builder.yml#L25-L29) 的 `mac.extendInfo` 增加输入监控用途说明，并在 [entitlements.mac.plist](file:///d:/projects/playground/interview-coder-cn/build/entitlements.mac.plist) 按需补充 —— 具体键名以实现时 Xcode / 系统提示为准。

## 5. 已知限制：Raw Input 设备区分在 Windows 上不可用于吞键决策

Windows 的输入管线顺序是 **低级钩子（`WH_KEYBOARD_LL`） → `RegisterHotKey` → Raw Input → `WM_KEYDOWN`**。对键盘而言，**被低级钩子吞掉的按键不会产生 Raw Input 包**（鼠标不同，鼠标的 Raw Input 包总是生成）。

推论：
1. `WH_KEYBOARD_LL` 回调里**拿不到设备信息**（`KBDLLHOOKSTRUCT` 只有 `vkCode` / `scanCode` / `flags` / `dwExtraInfo`，无设备句柄）。
2. 想用 Raw Input 判定设备、再用钩子吞键，在低级钩子层面存在**时序竞态**（钩子回调早于 Raw Input 包入队）。
3. 因此「只让第二键盘的普通键生效、主键盘原样放行」在 Windows 上无法用常规 API 实现，需要 `WH_KEYBOARD` 标准钩子做 DLL 注入（PowerToys 级复杂度、UIPI 与杀软风险高）或内核过滤驱动 —— 均已排除。

**本方案的实际保证**：靠「专属键位本身就不在主键盘上」（`F1`–`F24` / `ScrollLock` / `Pause` / 鼠标侧键）或「牺牲修饰键被整体接管」来保证不误吞，**不依赖设备身份**。设备识别仅用于诊断展示。

macOS 同理无法按设备区分键盘事件；若未来需要，可行路径是 `IOHIDManager` + `kIOHIDOptionsTypeSeizeDevice` 独占目标设备（该设备会被本应用完全接管），属独立课题。

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 本机无 MSVC，native 无法在本地编译验证 | 步骤 3 被阻塞 | 步骤 1 的纯 JS 闭环先做完；步骤 3 需先装 VS Build Tools |
| 默认键位从「左 Ctrl」改为「右 Ctrl」 | 用户肌肉记忆需要调整 | 三级回退（§2.6）+ 升级引导 + 横幅明示；一条开关即可回到原键位 |
| macOS TCC 授权 + `notarize: false` | 签名变化可能导致授权失效，用户需手动授权 | 授权失败一律降级 + UI 指引，不阻塞主流程 |
| Windows 杀软把「全局钩子 + 吞键」判为键盘记录器 | 安装失败甚至被查杀 | `install()` 失败即降级；不做进程注入；「无痕模式」开关允许用户完全关闭钩子 |
| `F5` / `F11` / `F12` 等被用户绑成单键 | 浏览器功能被接管 | `FUNCTION_KEY_CONFLICTS` 冲突徽章 + 预设二次确认弹窗明确列出被接管的功能 |
| Vite 对 workspace 软链源码的解析 | 渲染端构建失败 | 备选：renderer `resolve.alias` 指向 `packages/shortcut-tokens/src` |
| zustand persist 不会深合并 Shortcut 对象 | `hookKey` 缺失导致无痕绑定不生效 | bump `version: 8` + migrate 显式补齐 + 第 2 项单测覆盖 |
| 钩子被系统静默摘除 | 快捷键静默失效 | §2.7 健康检查自愈 + 自愈失败时状态回传，UI 提示 |
